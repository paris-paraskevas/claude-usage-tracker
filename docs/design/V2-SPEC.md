# Claude Usage Tracker v2 — product and engineering spec

Status: approved direction (2026-10-20): **A · Native** with **B's runway chart** as the dashboard hero.
Mockups: the "Usage Tracker Redesign" design canvas (rows A and B). This spec is the contract the
engine, the desktop UI and the Android widget are built against.

## 1. What the app is for

Heavy Claude Code users on Pro / Max / Team plans work against rolling limits: a 5-hour window and a
weekly window, plus per-model weekly scopes and paid extra usage. The app exists to support one
decision, without pulling the user out of their work:

> Keep going, slow down, compact, switch account, or wait for the refill?

Every surface answers, in this order:

1. How much headroom is left, and when does it refill?
2. At the current pace, will I hit the limit before the refill? (the most valuable number)
3. Which session is filling its context, and which sessions are waiting for my reply?
4. Is Claude itself having an incident?
5. (Teams) Which pooled account has headroom right now, and what did extra usage cost this month?

Lifetime stats are secondary and live in History.

## 2. Surfaces

| Surface | Attention | Shows |
|---|---|---|
| Tray icon | ambient | used % of the binding limit; corner badge for watch / will-hit; clock when limited; dimmed when stale |
| Tray flyout (left-click) | glance | verdict line, 5-hour + weekly bars, Dashboard / Overlay / Mute 1 h |
| Tray menu (right-click) | command | Open dashboard (default, bold), Show overlay ✓, Mute alerts ›, Refresh now, Settings, Quit |
| Overlay (replaces mini widget + HUD bar) | peripheral | one line at rest; expands in place on click (hover only highlights); pin; optional click-through |
| Dashboard | deliberate | Now · Sessions · Team pool · History, Settings behind the gear |
| Notifications | interrupt | only when actionable, once per episode |
| Android widget | glance away | 2×1, 2×2, 4×2 (see §9) |

## 3. Forecast and decision rules (engine)

All numbers, levels and alert decisions are computed by the engine. UIs only format.

Per limit (`five_hour`, `seven_day`, scoped `seven_day_opus` / `seven_day_sonnet`):

- `window_s`: 18000 for five_hour, 604800 for weekly scopes.
- `elapsed_pct = 100 × (window_s − seconds_to_reset) / window_s` (the "even pace" mark).
- `rate_pct_h`: least-squares slope of `used_pct` over the trailing fit window (five_hour: 30 min,
  weekly: 6 h), using only samples after the last reset. Needs ≥ 3 samples spanning ≥ 10 min
  (five_hour) or ≥ 1 h (weekly); otherwise `null` ("gathering"). Negative slopes clamp to 0.
- `projected_at_reset = used_pct + rate_pct_h × hours_to_reset` (may exceed 100).
- `eta_100`: epoch seconds when `used_pct` reaches 100 at `rate_pct_h`; `null` when rate is 0/null
  or the limit is reached; only set when it falls before `resets_at`.
- `sustainable_pct_h = (100 − used_pct) / hours_to_reset` (the "slow to X%/h" figure).
- `confidence`: `"low"` (just enough samples), `"ok"`.

Level of a limit (`level`):

| level | rule |
|---|---|
| `limited` | `used_pct ≥ 100` |
| `will_hit` | `eta_100` exists (projected ≥ 100 before reset) |
| `watch` | `80 ≤ projected_at_reset < 100`, or (rate unknown and `used_pct ≥ 90`) |
| `ok` | otherwise |

Hysteresis: a limit only drops from `will_hit`/`watch` to a lower level when `projected_at_reset`
is ≥ 5 points below that level's threshold, or the window resets.

Decision (one per state):

- `binding`: the limit with the highest level (`limited > will_hit > watch > ok`); ties → earliest
  `eta_100`, then highest `used_pct`. Scoped weekly limits only bind when the active model uses
  that scope; otherwise they are informational.
- `resume_at`: when any limit is `limited`, the latest `resets_at` among limited limits; else null.
- `title` / `detail`: short plain-English strings generated by the engine (tray tooltip, toasts,
  phone, flyout use them verbatim). Examples:
  - will_hit: "Limit around 16:26" / "14 min before the 16:40 refill. Slow to 19%/h to make it."
  - watch: "About 92% by 16:40" / "Close to the 5-hour limit at this pace."
  - ok: "On pace" / "5-hour 38% · refills 16:40."
  - limited: "5-hour limit reached" / "Back at 16:40." (mentions extra usage if enabled)
- `suggestion` (team pool only): the pooled account with the most 5-hour headroom whose weekly limit
  is not `limited`, if it has ≥ 20 points more headroom than the current account.

Staleness: `source.stale = true` when the newest usage reading is older than
`max(3 × expected_interval, 15 min)`, or the last fetch failed. Stale data is never shown as live.

## 4. Alerts (engine)

One toast per **episode**; an episode ends when the level falls (with hysteresis) or the window
resets. Kinds and default severities:

| kind | when | severity | phone push |
|---|---|---|---|
| `will_hit` | a limit enters `will_hit` | warning | yes |
| `limited` | a limit reaches 100% | critical | yes |
| `refilled` | a limited window resets | info | yes |
| `context_high` | active session context ≥ 90% | warning | no |
| `overage_high` | extra usage ≥ 80% of cap | warning | yes |
| `session_waiting` | Stop hook, user away ≥ 60 s | info | yes |
| `needs_approval` | Notification hook `permission_prompt` | warning | yes |
| `incident` | status indicator worse than `none` | info | no |

- Mute: "until refill", "1 hour", or quiet hours (setting). Muted alerts still appear in state.
- Housekeeping messages ("Opening sign-in…", "You're on the latest version") are UI feedback,
  never toasts and never pushed to the phone.
- The old fixed 20% threshold pings and the per-percent 95–100 "danger" pings are removed.

## 5. State v2 (engine → UIs)

`GET /api/v2/state` returns the full state; `GET /api/v2/events` is Server-Sent Events: on connect
one `state` event with the full state, then one `state` event per `rev` change (full state; it is
small because history and all-time are separate topics). Countdowns are computed client-side from
absolute epoch timestamps. A literal example lives in `docs/design/state-v2.example.json`.

```text
{
  schema: 2, rev: int, generated_at: epoch_s,
  source: { kind: "statusline"|"api", updated_at: epoch_s, age_s, stale: bool,
            auth: "ok"|"expired"|"missing", error: str|null },
  account: { email, name, org, plan },
  decision: { level, binding: limit_id|null, title, detail, resume_at: epoch_s|null,
              suggestion: { email, five_hour_left_pct, label }|null },
  limits: [ { id, label, scope: "all"|"opus"|"sonnet", used_pct, resets_at, window_s,
              elapsed_pct, level, binding: bool,
              pace: { rate_pct_h|null, sustainable_pct_h|null, projected_at_reset|null,
                      eta_100|null, confidence: "gathering"|"low"|"ok" } } ],
  overage: { enabled, used, limit, currency, pct } | null,
  sessions: [ { id, project, cwd, state: "working"|"waiting"|"needs_approval"|"idle",
                since: epoch_s, active: bool, model,
                context: { pct, tokens, window }, tokens_5h } ],
  service: { indicator: "none"|"minor"|"major"|"critical"|"unknown", description, url,
             affected: [str] },
  team: { signed_in, email, role: "admin"|"member"|null, team, device_ok,
          pool: [ { email, name, five_hour_pct, five_hour_resets_at, seven_day_pct, level,
                    month_spend, currency, device, updated_at, is_me } ] } | null,
  alerts: [ { id, kind, severity, title, body, at, muted: bool } ],
  mute: { until: epoch_s|null, reason: "refill"|"hour"|"quiet_hours"|null },
  app: { version, update: { available, version, url }|null,
         remote: { enabled, paired, relay_url, last_sync }, overlay: { shown, pinned } }
}
```

Lazy topics: `GET /api/v2/history?window=five_hour|seven_day` (samples since the last reset:
`[[t, used_pct], …]`), `GET /api/v2/alltime?range=7d|30d|all`, `GET /api/v2/team/ledger?month=YYYY-MM`.

Actions: `POST /api/v2/actions/<name>` with a JSON body — `refresh`, `login`, `update`,
`check_update`, `mute` `{for: "refill"|"hour"|"off"}`, `overlay` `{show?, pin?}`, `open_dashboard`
`{view?}`, `remote_pair`, `remote_rotate`, `remote_unpair`, `team_login_start` `{email}`,
`team_login_verify` `{email, code, username?}`, `team_logout`, `team_claim_device`,
`team_connector_token`, `install_statusline`. Settings: `GET/PATCH /api/v2/settings` (typed,
validated server-side). Hooks: `POST /api/v2/hooks/claude`.

Compatibility: `/api/usage` (v1 snapshot) and the relay payload stay, built from v2 by an adapter,
for the MCP server and the Android app. The relay payload additionally carries `decision` and each
window's `pace` so the phone can show the verdict.

All local endpoints keep the loopback Origin/Host guard.

## 6. Design system (desktop)

Native Windows 11 feel; the identity lives in the data visuals.

- Type: `"Segoe UI Variable Text", "Segoe UI", system-ui, sans-serif`; display
  `"Segoe UI Variable Display"`. Ramp (px/line-height): caption 12/16, body 14/20, body-strong
  14/20 600, subtitle 20/28 600, title 28/36 600, hero numbers 34/40 600. Tabular numerals on all
  numbers. Minimum 12 px.
- Spacing: 4 px grid; cards 16–18 px padding; 16 px gaps. Radii: 4 (controls), 8 (cards, windows).
- Theme: follows the OS (`prefers-color-scheme`); accent passed from Python (`--accent`), default
  `#005FB8` light / `#60CDFF` dark. Supports `forced-colors: active` and `prefers-reduced-motion`.
- Neutral tokens (light / dark): bg `#F3F3F3`/`#202020`, layer `#F9F9F9`/`#272727`, card
  `#FFFFFF`/`#2B2B2B`, stroke `#E5E5E5`/`#3A3A3A`, text `#1B1B1B`/`#FFFFFF`, text-2
  `#5C5C5C`/`#C5C5C5`, track `#E6E6E6`/`#3D3D3D`.
- State tokens (light / dark), always paired with an icon and a word:
  - ok `#0072B2`/`#4FA8E0` (check in circle, "On pace")
  - watch fill `#E69F00`/`#F2B544`, text `#8A5A00`/`#F2B544` (clock, "Watch pace")
  - will_hit `#C4470A`/`#F07B3F`, text `#A9400A`/`#F49B6E` (triangle, "Will hit limit")
  - limited same hue, solid surface (clock, "Limit reached")
  - stale `#8A8A8A` (slashed circle, "As of 14:31")
  - service ok `#0F7B0F`/`#6CCB5F`
- Bullet bar: track 10 px; used fill in the level colour; hatched projection from used to
  `min(projected, 100)`; 2 px "even pace" tick at `elapsed_pct`; `role="meter"` with a full
  sentence `aria-label`.
- Runway chart (Now view hero, for the binding limit): x = window start → reset; y 0–100 with a
  dotted LIMIT line; actual usage line (from `/api/v2/history`); dashed even-pace diagonal; dashed
  projection in the level colour from now to 100% (or to the reset); a shaded "dry" band between
  `eta_100` and the reset with its length labelled; a "now" marker; a thin line at
  `sustainable_pct_h` labelled "X%/h makes it". Readouts above it: **Runway** (time to `eta_100`)
  vs **Refill** (time to reset). Light and dark from tokens.

## 7. Dashboard views

- **Now**: header (title, service chip, "Updated hh:mm", refresh) → verdict banner (icon, title,
  detail, actions: suggestion "Switch to … — N% left" which runs sign-in, and "Mute until refill")
  → runway chart → limit cards (5-hour, Weekly with Opus/Sonnet rows) → three cards (Active
  session context with a 90% compact mark, Waiting for you, Extra usage).
- **Sessions**: table sorted waiting/needs-approval first, then active: project, state chip,
  context bar, tokens (5 h), last activity. Empty state explains the idle hook in Settings.
- **Team pool**: signed out → sign-in (email → code → username, consent). Signed in → pool table
  sorted best headroom first (account, 5-hour + refill, weekly, level chip, month spend per
  currency, last device), the current account marked; month ledger with month picker (capped at
  the current month) and CSV export; admin-only "claude.ai connector" card.
- **History**: usage over time (5-hour and weekly), all-time totals, streaks, labelled heatmap with
  a Less→More legend, models and projects; range 7d / 30d / All.
- **Settings** (gear): Alerts (which alerts, quiet hours, status components), Overlay (fields,
  click-through, opacity, auto-hide in full screen), Phone (pairing QR, relay URL, conversation
  mirror), Team (time zone), Data source (statusline install, refresh), About (version, updates,
  logs).
- Every panel designs loading, empty, error and stale states.

## 8. Overlay, tray, flyout (desktop)

- **Overlay**: one frameless always-on-top window, `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW`; optional
  click-through (`WS_EX_LAYERED | WS_EX_TRANSPARENT`). At rest 30 px tall:
  `▲ 5h 64% limit ~16:26 │ 7d 41% │ ctx 73% │ 1 waiting` (fields configurable; fixed-width
  numeric slots). States: ok, will-hit, stale (greyed, "as of hh:mm"), limited (solid, "back at
  16:40 (in 14 m)"). Expands in place to a 340 px panel on click (owner's call: hover only highlights); pin keeps it open. Snaps to
  edges; hides when a full-screen app or presentation is active.
- **Tray icon**: drawn at the exact small-icon size for the current DPI (16/20/24/32), in taskbar
  colours from `SystemUsesLightTheme`. Default style (owner's choice after the first test build):
  two vertical bars, 5-hour | weekly, filled to the used %; fill in taskbar colour when ok, amber
  for watch, vermillion for will-hit, full vermillion when limited, grey when stale. Alternative
  "number" style (setting `overlay.tray_icon`): the binding limit's % as 2 digits with a status
  bar along the bottom edge (a corner badge covered the second digit at 16 px); clock when
  limited. Redrawn only when the icon key changes. Tooltip ≤ 127 characters, from
  `decision.title` + `detail`.
- **Flyout**: frameless window above the tray (≈ 300 px wide), closes on blur.

## 9. Android widget

Per the A-Android board: 2×1 (binding limit %, thin bar, "▲ limit 16:26" or "Refills 16:40"),
2×2 default (header + 5-hour and Weekly with %, bar, absolute refill time + pace line), 4×2 (both
limits side by side + pace + account + refresh). Light/dark with dynamic colour; state colours as
fixed day/night pairs; stale dims values and says "Desktop offline · as of hh:mm"; at 100% shows
"back hh:mm". Absolute times only (no ticking countdowns). Reads `decision` and `windows[].pace`
from the relay payload; falls back gracefully when absent (older desktops).
